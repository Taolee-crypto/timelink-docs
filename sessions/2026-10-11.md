## 1. Player 오프라인 .tl3 재생 복구

### 문제 발견

오프라인 .tl3 재생이 실패:

- 헤더크기 오류 (1차) — main.js Worker의 잘못된 오프셋 (data[6], LE)
- 복호화 실패 (2차) — Worker가 예전 XOR 방식 사용, 파일은 AES-256-GCM + SHA256 체인
- Unsupported state or unable to authenticate data (3차) — AES-GCM 인증 실패

### 근본 원인 (3가지)

원인 1: 헤더 파서 endian/offset 오류

기존 (little-endian, 오프셋 6):
    const hdrLen = data[6]|(data[7]<<8)|(data[8]<<16)|(data[9]<<24);

수정 (big-endian, 오프셋 5):
    const hdrLen = ((data[5]<<24)|(data[6]<<16)|(data[7]<<8)|data[8])>>>0;

원인 2: Worker가 예전 XOR 방식 — 파일의 aead: AES-256-GCM인데 Worker는 xorKey 찾음

원인 3: first_offset이 실제 payload 시작과 어긋남 (18바이트)

### 해결

1. main.js Worker를 AES-GCM + SHA256 체인으로 재작성
2. first_offset 대신 9 + hl 사용
3. 백엔드 first_offset 계산 안정화 루프

### 검증

- T0 검증: 일치 O
- AES-GCM 복호화: 성공 O (plain 첫 8바이트 = fffb540000000000)

## 2. 3자 로직 통일

### 최종 파일 포맷 (.tl3 v3)

    [0..3]   "TLNK" (0x54 0x4C 0x4E 0x4B)
    [4]      0x03 (버전)
    [5..8]   headerLen (uint32 BE)
    [9..]    JSON 헤더
    [9+hlen] mp3 세그먼트 × N

### 키 유도 (모든 컴포넌트 동일)

    T_0 = SHA256(fid + hash_mp3 + salt)
    K_n = SHA256(T_{n-1} + lic + "K"+n)
    IV  = [4B 0][8B n (BE)] (12바이트)

### 컴포넌트별 상태

| 컴포넌트 | first_offset | 파서 | 상태 |
|---|---|---|---|
| 백엔드 tl3v3.ts | 안정화 루프 | BE | OK |
| 프론트 tl3.js | 9 + hlen | BE | OK |
| Player main.js | 9 + hl | BE | OK |
